# HR 语境 SQL 练习台：交互与游戏感设计方案

任务：Q4-astra-design；日期：2026-10-12；状态：待实现设计稿。

目标是让每次操作都有清楚的回应，让一次通过成为看得见的推进：**操作有回声，结果有依据，通过有落点，下次能接上。** 不新增奖励经济，不改变 SQLite 判题口径。

本次仅新增本文档；下述文件、函数、样式改动均为后续实现建议。依据是源码静态阅读与任务提供的实测现状；本文没有执行浏览器体验验证。文件引用均相对于仓库根目录。A 级基线以本次任务中的原文为准，不用源码旧注释替代。

## 1. 现状诊断

### 1.1 已有基础与诊断边界

保留任务给定的事实：离线单 HTML、约 1.99 MB、120 题六段、11 张表与 3 个视图、`dbquest.v2` 本地进度；两栏加抽屉，窄屏左栏变抽屉；顶栏已有 `#stat-stage` 与 `.bar > i#stat-bar`，进度由 inline width 百分比驱动，已有 220ms 宽度过渡；XP、连续天数、今日目标、总进度位于默认 hidden 的 `#record-panel`。没有音效，页面 UI emoji 为 0。

`src/style.css` 已有四个关键帧：`hr-fade-up` 220ms、`hr-pop` 240ms、`hr-shake` 260ms、`hr-summary-in` 240ms；`src/app.js` 的 `setBusy` 已禁用按钮、设置 `aria-busy` 并替换忙态文案；`bindUi` 已支持 Ctrl/Cmd+Enter、补全方向键/Enter/Esc；`judgeNow` 成功后已有 `focusNextAction`；`renderTable` 已将行淡入封顶为前 20 行。问题不是缺少这些功能，而是反馈层级与状态交接不完整。

判题细节以调用链为准：`runNow` 执行用户 SQL，`referenceResult` 在隔离的参考库执行参考 SQL 并缓存，`judgeNow` 将两个结果交给 `src/judge.js::judgeResult`；通过不要求 SQL 文本相同，列名不同也可能按列序对齐通过。设计不能把运行成功说成通过，也不能把提示说成扣分理由。

### 1.2 逐交互点的反馈断裂

| 交互点 | 代码事实 | 反馈缺口与影响 |
| --- | --- | --- |
| 进入题目 | `src/app.js::boot` 恢复 `state.current`，再退回今日计划或首题；`renderDetail` 恢复草稿，清掉结果与判定。 | 用户能接着写，但没有贴近编辑器的“草稿已恢复／尚未判题”说明；恢复过程容易像一次普通重绘。 |
| 读题 | `renderDetail`、`renderTags`、`renderSyntaxCards` 呈现任务、考点、语法卡；`syntaxCardNode` 确认后替换原卡并播报。 | 题面信息充分，但“已看过，开始尝试”没有把焦点交给编辑器或替换后的可用节点；原按钮被移除，键盘阅读到动手之间有断点。不能用阅读停留时长推断已掌握。 |
| 写 SQL | `onSqlEdit` 每次保存；`updateSuggest` 重建候选，`moveSuggest` 切高亮，`applySuggest` 插入并恢复光标。 | 保存结果无就地反馈；编辑后旧结果和旧通过文案没有失效标记。候选只有 `mousedown` 应用路径，原生按钮的键盘 click 路径不足；`bindUi` 拦截 Tab，Esc 无候选时仅 blur，出口不明确。 |
| 运行 | `doRun` 忙态后 `setTimeout(..., 0)` 调用同步 `runNow`；成功显示表格与行列数。 | 成功没有靠近操作按钮的“已运行，尚未判题”确认，之前的判错卡可能仍在；0ms 定时器提供让出任务的机会，但不能据此断言忙态已实际绘制。`doRun` 没有与判题同等的题号快照。 |
| 判题 | `doJudge` 捕获题号，切题后丢弃；实际 SQL 在 `judgeNow` 内读取；两按钮互斥禁用。 | 缺少提交时的 SQL 版本边界。`src/db.js::runQuery` 为同步 WASM，计算时主线程不能持续响应输入；不能承诺进度动画能一直流畅或立即取消。 |
| 未通过 | `renderVerdict` 淡入、编辑器 shake；`diffTypeOf`、`firstActionHint` 已给差异和建议；`renderRunError` 优先 `sqlTriage` 再 `explainError`；判错自动展开提示。 | 错误解释已存在，但编辑器晃动强调挫败，新增提示可能在上方不可见；没有稳定的“回到 SQL 修改”动作。执行错误、结果不符、题库待复核需要更鲜明地区分。 |
| 通过 | `judgeNow` 调用 `renderVerdict`、`renderPostPass`、`renderNextAction`，然后聚焦 `#btn-next-primary`。 | 成功卡仍调用 `diffTypeOf`：无差异时该函数兜底为“行集不一致”，列名提示也可能被呈现为差异。通过与否出现自相矛盾的文字分支；此外成功副文案仍含 XP。 |
| 连续通过 | `renderStats` 改进度条宽度；`renderNav` 整体重建目录；`fb.duplicate` 与首次完成分支已存在。 | 同一段连续完成不同题，没有“本次从 n 到 n+1”的局部归因；重复提交、回看、真正首次完成容易共用庆祝。需要区分事件，不能加连击计数。 |
| 段通关 | `renderSectionSummary` 有考点、跟练与复查信息；段末与今日目标可合并；`renderPostPass` 为段徽章播放 pop。 | 总结位于结果、答案、过关解锁之后，主按钮先获得焦点，里程碑可能在屏外。`renderSectionSummary` 每次展示都重播动画，`firstShown` 只用于记录已看；回看整段仍可能庆祝。末段的总结文案还需区分“第六段完成”和“120 题完成”。 |
| 切题 | `selectLevel` 重绘并保存；键盘选题后焦点回到目录 li；`jumpToQuestion` 按需清筛选。 | `renderDetail` 对未通过题也调用 `renderNextAction`，容易提前出现“下一项”；窄屏关闭目录后再聚焦隐藏的题行有风险。旧补全、今日收束等瞬态内容没有在此统一清理。 |
| 退出 | `saveProgress`、`onSqlEdit` 持续保存；`showTodayWrap` 有收束；`safeStorage` 可降级为内存；`L.saveState` 返回写入结果。 | 只有达成目标等路径容易看到收束，没有随时可用的轻退出入口；成功保存与仅内存暂存不能用同一句保证。内存 stub 的写入也会返回成功，因此只看 `persistence` 不足以判断落盘。 |

### 1.3 需要正面处理的基线偏差

这几项是源码中的残留，不把它们当成设计许可：

- `index.html` 与 `renderStats` 仍呈现 XP／连续天数；`judgeNow`、`todayWrapText` 还有加 XP／不扣 XP 文案。收进折叠面板不等于下线。
- `renderAttempts` 显示“独立尝试剩余 N 次”，`src/levels.js::recordLearningAttempt` 有有效判错减次数、耗尽转 guided 的逻辑。虽未锁住运行或画生命值，仍有有限尝试的惩罚感；本案不能只换个称呼保留它。
- CSS 实际含 13px（如 `.syntax-row`、`.today-summary`、`.qa-answer`），超过注释声明的四档；`:root` 实际色值也超过六种。新方案应收敛，不再增加 token。
- 桌面 `.layout` 为 `280px minmax(640px, 1fr)`；但 `max-width:968px` 下 `.detail` 没有 640px 下限。此处与任务的无条件下限存在边界冲突，第 5 节单列，不暗中宣布窄屏已获豁免。

## 2. 设计原则

1. 每次运行或判题先确认受理，最终状态在计算结束后的下一次可绘制机会出现，动画不得延迟内容或操作可用时间。
2. 每个反馈区只给一个明确主动作，文字必须区分已运行、未通过、已通过、题库异常与结果已过期。
3. 成就只来自真实完成与知识回顾，重复提交、回看和改写不产生虚构进度，也不建立连续奖励或失败惩罚。
4. 普通操作只做局部短反馈，首次段完成才提升反馈层级，整个产品只维护三种关键帧与两种过渡。
5. 禁用动画、只用键盘或保存失败时，状态含义、下一步入口和已有成果仍然可理解、可到达。

## 3. 方案清单

### 3.1 界面落位与共同规格

保留左侧主线、主列、右抽屉；顶栏继续只承担定位与段进度。主列中，读题区保持业务任务为中心；编辑器标题旁增加一条 12px 状态文字，原 `#run-hint` 承担最近操作摘要；`#verdict` 是唯一判定反馈卡。需要段总结时，将现有 `#section-summary` 放在判定之后、`#next-action` 之前，不复制第二张总结。过关解锁仍在其后，学习记录默认收起。

四档固定为 12／14／16／20px，现有 13px 归并到 14px。采用六个实色：背景 `#F7F6F3`、面板/编辑器文字 `#FFFFFF`、正文/编辑器底 `#262421`、装饰边框 `#E6E3DD`、强调/需处理 `#B23A2E`、完成 `#2F7D5B`。其余旧色 token 映射到这六个值；浅底统一用背景或面板，次要信息用字号与字重分层，不再加浅色、渐变、滤镜派生色。遮罩可用正文色加透明度；动画透明度合成不作为新增语义色。错误、警告用明确标题区分，不另设第七色。深色编辑器保持视觉中心；必要的输入边界用正文色，浅底焦点用强调色、深色编辑器焦点用白色，不用低对比装饰线承担交互识别。

桌面主列至少 640px，目录不挤占此下限；目录在窄屏仍改抽屉。严格按当前任务执行时，低于主列加边距所需宽度的视口必须允许横向访问 640px 内容，不能裁掉按钮；更合适的窄屏下限豁免见第 5 节，未列为默认采用项。

状态按真实事件变化：进入题目 → 编写；编写可直接判题，也可运行后再判题；未通过 → 修改；通过 → 自选下一项或收束。修改 SQL 后显示“已修改，需重新运行或判题”，但历史已完成记录不撤销。运行结果与本次判定分别记所属题号和 SQL 版本，不能互相冒充。

### 3.2 动效预算与时间契约

以下时间从对应 DOM 状态写入的时刻算起，不含 SQLite 计算时间。除注明外，延迟为 0ms、播放一次，无无限循环；所有内容与按钮在 0ms 就存在且可用。

| 动效原语 | 属性、时长与缓动 | 使用范围 |
| --- | --- | --- |
| A：局部进入，复用 `hr-fade-up` | opacity 0→1、translateY 4px→0；常规 160ms，结果行 220ms；`cubic-bezier(.2,0,0,1)` | 题目标题/任务摘要、失败卡、新展开提示；结果前 20 行同时播放，不做逐行瀑布延迟。 |
| B：完成确认，复用 `hr-pop` | opacity .8→1、scale .98→1；240ms；`cubic-bezier(.2,0,0,1)`，无回弹超调 | 仅本次首次通过的短标题；不用整张大卡缩放。 |
| C：段总结，复用 `hr-summary-in` | opacity .8→1、scale .985→1；240ms；同上 | 本次真正跨过段完成边界的总结；覆盖普通通过的 B，不叠加徽章 pop。 |
| D：段进度，替换现有 width transition | `transform:scaleX`，左侧原点；220ms；同上 | 保留 `.bar > i#stat-bar`，i 固定满宽；同段首次完成时延迟 120ms，由旧比例到新比例；切段/初次加载直接设终值，不演成获得进度。 |
| E：按压反馈 | translateY 0↔1px；80ms；`ease-out` | 可操作的主次按钮按下/释放；禁用态不位移。 |

关键帧由四种减为三种，移除 `hr-shake`；过渡只保留 D、E。无需新关键帧：普通回应、完成确认、段落结束已覆盖三个语义层级，更多动画会让重复练习变慢、增加组合测试成本。未列出的控件开合与文字更新均为 0ms、无缓动；不动画化 width、height、top、left、颜色、阴影或滤镜，也不用需要额外验证的裁切动画。

普通首次通过的可见节奏：0ms 写入通过标题、真实段计数、下一步并交接焦点；标题 B 播放 0–240ms；进度 D 播放 120–340ms。按钮绝不等到 340ms 才能点。段通关以 C 替换 B，其余相同；数字直接更新，不逐字滚动。

所有条目共享以下可访问性与中断规则：

- `prefers-reduced-motion: reduce` 下持续时间与延迟都归零、transform 直接终值，内容、焦点、计数、按钮时机与正常模式相同；不依赖 `animationend` 才完成业务动作。
- `#live-status` 作为练习反馈的唯一 polite 播报器；`#verdict` 改为有标题关联的普通 region，不重复 live 播报整张卡。若本次焦点交接已通过目标的描述读出结论，就不再向 live 区写同一句；不移焦时才用 live 区播报结论。问一问保留自己的局部反馈域，避免同一事件双播报。
- 成功后仍使用 `focusNextAction`；仅在提交以来用户没有主动移走焦点时执行。目标在屏外时一次即时最小滚动使其可见，避开 sticky 顶栏；不用平滑滚动抢走输入注意力。
- 每次操作持有题号、SQL 快照/版本与递增事件标识；切题或新操作使旧装饰回调失效。`replayAnim` 清理旧监听与取消态，同一节点每种动效最多一个实例；不永久设置 `will-change`。
- 原生按钮、清晰焦点轮廓、文本状态是默认；下面每项的“减弱动画按共同规则”表示完全静态仍能完成同一动作，不表示删掉反馈。

### 3.3 按交互点安排的设计项

#### A. 全流程：先清理违反基线的奖励与惩罚残留

- **触发条件：** 初始化、学习记录展开、任一判题与今日收束。
- **视觉与动效：** 移除 XP、连续天数、剩余尝试次数和相关奖励文案；0ms 静态变化，无缓动。学习记录仅保留今日成果、已完成、待修正、待复查与保存状态；同时执行六色/四字号收敛。
- **文案：** “已完成 12 题 · 待复查 2 题”；“可以继续修改，也可以查看提示”。不把次数改叫能量或机会。
- **可访问性：** 删除对应可见与隐藏播报文案；统计区仍有名称；收起按钮与 Esc 返回入口。减弱动画按共同规则。
- **实现落点：** `src/index.html::record-panel/q-attempts`；`src/style.css` token 与 13px 规则；`src/app.js::renderStats/renderAttempts/judgeNow/todayWrapText`；`src/levels.js::recordLearningAttempt/creditLearningEvent`。建议停止新 XP/连续奖励累计，旧存档字段保留兼容但不参与体验；判错只累计供提示分层的事件，不递减可用次数、不强制进入跟练。跟练来自主动查看答案或主动选择；旧完成记录不重写，去重、复查、今日集合保留。此项涉及学习状态机，不能伪装成纯 CSS 修饰。
- **优先级／改动量：** P0；约 130–210 行，含上述文件及旧存档适配；不改 `judge.js` 的对错口径。

#### B. 进入题目：说明从哪里接上

- **触发条件：** 首次打开、恢复上次题目、明确选择另一题；普通统计重绘不触发。
- **视觉与动效：** 标题与任务摘要共同使用 A，0–160ms；编辑器与整张题面不移动。状态文字同步出现，SQL 恢复不逐字播放。
- **文案：** 无草稿“本题尚未判题”；有草稿“已恢复本题草稿，继续编辑”；历史通过题“本题已完成，可改写练习”。不标成“已掌握”。
- **可访问性：** 首次启动不抢焦点；用户主动选题后聚焦 `#q-title`（程序可聚焦），再由“开始写 SQL”到编辑器；读屏获得题号/段内位置与恢复状态，不朗读整题。减弱动画按共同规则。
- **实现落点：** `src/app.js::boot/selectLevel/renderDetail/renderNav`；`src/index.html::q-title/editor`；`src/style.css`。同时修正 `renderNav` 中 `sectionIndexOf(sec, q)` 应传题目 id 的位置，避免播报第 0 题。
- **优先级／改动量：** P1；约 35–55 行。

#### C. 读题与求助：每次展开都能回到动手

- **触发条件：** 语法卡确认、展开提示、打开表结构/方言、使用问一问。
- **视觉与动效：** 仅新提示/新语法内容用 A，0–160ms；不对容器高度做动画。抽屉与问答内容即时开合；最后一张未读语法卡确认后呈现“开始写 SQL”入口，不要求确认所有卡才能作答。
- **文案：** “已展开提示 2/3”；“开始写 SQL”；“返回编辑器”。内容缺失时沿用明确的缺失说明，不补造 HR 规则。
- **可访问性：** 确认后焦点去替换后的回看按钮，多卡时不越过未读卡；“开始写 SQL”才转到 textarea。`aria-expanded/controls` 同步；抽屉打开记录来源并聚焦页签/搜索，关闭返回来源，浮层内 Tab 可循环、Esc 可退出，背景不接收焦点；提示播报一次。减弱动画按共同规则。
- **实现落点：** `src/app.js::syntaxCardNode/revealNextHint/renderHints/qaSetOpen/openDrawer/openRail/closePanel/bindUi`；`src/index.html` 抽屉语义与入口；`src/style.css`。
- **优先级／改动量：** P1；约 55–90 行。求助内容的额外淡入属于 P2，可先只做焦点与展开反馈。

#### D. 写 SQL：保存有依据，旧结果有边界

- **触发条件：** 输入、应用补全、保存结果变化，以及已有运行/判题结果后再次修改。
- **视觉与动效：** 编辑器标题旁静态状态文字；首次修改立即标旧结果“来自上次运行”，旧判定“上次判定：通过／未通过”，下一步通过按钮收起。保存仍按现有每次编辑执行，连续输入停止 400ms 后合并显示一次保存反馈；400ms 是提示合并，不是延迟保存。补全无进出动画。
- **文案：** “草稿已保存到此浏览器”；或“草稿仅暂存在本页，关闭可能丢失”；“已修改，需重新运行或判题”。仅当 `STORAGE_OK` 且保存确实成功才称已保存。
- **可访问性：** textarea 有显式名称；常规保存不逐键播报，保存失败仅首次或状态改变时播报。保留补全 ↑↓、Enter、Esc；候选保留原生按钮，键盘激活与指针走同一应用路径，焦点进入候选区不提前销毁候选。Esc 先关候选，再次 Esc 聚焦首个可用操作按钮，Shift+Tab 正常后退；Tab 缩进提示必须说明出口。减弱动画按共同规则。
- **实现落点：** `src/app.js::onSqlEdit/saveProgress/updateSuggest/moveSuggest/applySuggest/hideSuggest/bindUi`；`src/index.html::editor/sql-input/run-hint`；`src/style.css`。快照失效不删除历史 `passed`，也不重置复查记录。
- **优先级／改动量：** P0；约 60–100 行，共享快照与保存反馈逻辑见 E/L，不重复估算。

#### E. 运行：确认“跑出了什么”，不冒充通过

- **触发条件：** 点击运行或 Ctrl/Cmd+Enter，输入非空且数据库可用。
- **视觉与动效：** 按下用 E；0ms 设置忙态并清除当前判定的有效性标记，保留历史结论为历史。发起时捕获题号与 SQL；通过绘制让步后运行同步查询，不加人为最短等待。完成后按钮立即恢复，摘要与表格同帧更新；前 20 行用 A 的 220ms，同步淡入，第 21 行起静态，结果页签切换不重播。
- **文案：** “运行中…” → “已运行：N 行、M 列；尚未判题”。零行明确“查询执行完成，返回 0 行；尚未判题”；截断沿用真实上限说明，不能写完整结果已返回。
- **可访问性：** 两按钮 disabled/aria-busy 保持互斥；运行不强制转移编辑器光标，完成播报一次摘要。结果 tab 增加 tablist、aria-selected、tabpanel 关联和方向键操作。空输入聚焦编辑器并给出文字。减弱动画按共同规则。
- **实现落点：** `src/app.js::doRun/runNow/setBusy/showResultTab/renderTable/bindUi`；`src/index.html::result-block/run-hint`；`src/style.css`。可采用绘制帧后再排执行任务的调度，不能只用 0ms 数字作为已绘制证据；不得增加伪进度条或伪取消按钮。
- **优先级／改动量：** P0；约 55–90 行，含运行/判题共用的事件快照与过期保护。

#### F. 判题：受理、计算、结论只有一个状态来源

- **触发条件：** 用户提交判题；不要求事先运行。
- **视觉与动效：** E 按压，0ms 忙态；捕获题号、SQL 版本、来源焦点。计算返回后同一次渲染提交判定、结果、进度、下一步，视觉层再选 A/B/C；无固定等待、无倒计时。运行/判题互斥沿用现有 guard。
- **文案：** “判题中…”；最终只允许“通过”“未通过”“SQL 执行错误”“题库待复核”之一。参考失败、行数对账异常均不记用户失败，初始化失败保留重试入口。
- **可访问性：** busy 与结论分开，最终合并播报一句；SQL 计算期间不会假称可响应取消。若已切题，旧事件不更新新题内容、播报或焦点；同题提交后已编辑，保留草稿，结论只能标为提交版本的历史结果，不能对当前草稿庆祝。减弱动画按共同规则。
- **实现落点：** `src/app.js::doJudge/judgeNow/setJudgeLoading/renderVerdict/requireDb`；`src/index.html::verdict/live-status`。通过与否仍由 `src/judge.js::judgeResult` 决定。
- **优先级／改动量：** P0；约 25–45 行，复用 E 的调度与快照。

#### G. 未通过：看清一个证据，做一个修正

- **触发条件：** 结果集不符或 SQL 执行报错；题库异常进入 F 的中性分支。
- **视觉与动效：** 失败卡 A，0–160ms，编辑器不再 shake。顺序固定为结论 → 首个差异证据 → 一个建议 → “回到 SQL 修改”；更多差异继续折叠。自动新增提示只在摘要说明“已展开提示 N/M”，不同时让上下两块都动画化。
- **文案：** 结果不符：“未通过：你的结果比预期多 2 行”（仅在实际行数支持时）；建议：“可以检查 WHERE 条件是否遗漏”；语法错误先保留引擎原文，再给 `sqlTriage/explainError` 的解释。不说“只差一步”，不把推测原因说成诊断事实。
- **可访问性：** 不自动拉走正在输入的光标；“回到 SQL 修改”恢复原光标/选区并使编辑器可见。“查看新提示”是次动作，激活后聚焦对应提示；更多差异用原生 details。读屏播报结论及建议，不一次朗读所有行。减弱动画按共同规则。
- **实现落点：** `src/app.js::renderVerdict/renderRunError/firstActionHint/attachReviewTools/renderHints/judgeNow`；`src/index.html::verdict`；`src/style.css`。提示按实际新失败分层，不再通过剩余生命/次数推导；重复同一判错不重复解锁或堆叠播报。
- **优先级／改动量：** P0；约 35–60 行，移除 shake 的工作计入共同动效。

#### H. 通过：把成功、知识与下一步接在一起

- **触发条件：** 提交版本判定通过且题库可判；只有首次完成触发 B 与段进度 D。
- **视觉与动效：** 0ms 显示通过标题、结果摘要及下一步；首次通过标题 B，进度按 120–340ms 的 D。只调用失败差异分类来解释失败；成功时列名差异单独作“列名提示”，不能渲染“行集不一致”。普通通过不播放整块结果与标题双重动画；判题场景的表格静态。
- **文案：** “通过 · 首次完成”；“结果集与预期一致。第 2 段已完成 7/20。”；“本题练习：{knowledge_point}”。看过答案时另写“本次为跟练完成；已安排复查”（仅状态确实如此）。复查真正 resolved 才写“复查完成”。过关解锁标题建议改“本题回顾”，保留真实易错点/方言说明。
- **可访问性：** 延续焦点到 `#btn-next-primary`，以 `aria-describedby` 关联短通过摘要；受理后用户另行移动焦点则只播报，不抢回。长解释静态可读，成功含文字不只变绿。减弱动画按共同规则。
- **实现落点：** `src/app.js::judgeNow/renderVerdict/diffTypeOf/renderPostPass/renderNextAction/focusNextAction/renderStats`；`src/index.html::post-pass-block/next-action`；`src/style.css`。
- **优先级／改动量：** P0；约 45–75 行。

#### I. 连续通过与重试：让段进度承担推进感

- **触发条件：** 同一段不同题首次完成，或同题重复提交、改写通过、历史回看。
- **视觉与动效：** 每道真正新完成题重复 H 的短节奏；在成功卡显示本次“本段 6/20 → 7/20”，留到下次操作，不做自动消失 toast。复查完成只更新复查文字；已完成题不增长段进度、不播放 B/D。刷新和切段直接定位进度，不能从零跑满。
- **文案：** 重复同 SQL：“通过 · 与上次结果一致，完成题数未变化”；改写已完成题：“改写通过，本题已完成”；不出现“连续 3 题”或奖励倍数。
- **可访问性：** 进度条增加 progressbar 名称、min/max/now 与“第 N 段，已完成 n/m”的 valuetext；装饰性变化不另播报。目录更新后保留当前项语义与可见位置，避免无关重绘丢焦点。减弱动画按共同规则。
- **实现落点：** `src/app.js::renderStats/renderNav/judgeNow`；`src/index.html::.bar/#stat-bar`；`src/style.css::.bar i`。首次进度依据 `passed` 的前后差，不单凭“通过”；去重沿用 `src/levels.js` 事件结果。今日目标等持久状态从 `L.goalMet(state)` 读取，不把重复事件返回的默认 `credit.goalMet=false` 当成目标退回未完成。
- **优先级／改动量：** P1；约 30–50 行。D 的替换与 ARIA 属于 P0，通过事件区分必须与 H 同批完成。

#### J. 段通关：只在真正的边界停一拍

- **触发条件：** 本次提交使所在段从未完成变为全部题已完成；不以正在做第 20 题作为条件，也不以 `firstShown` 单独判定庆祝。
- **视觉与动效：** 总结在判定与下一步之间，用 C 的 240ms 替代 B；段进度 D 走到 100%。段完成与今日目标同时到达时，保留现有合并逻辑，只一张总结、一条播报。回看静态展示，不再播放徽章 pop。
- **文案：** “第 2 段完成 · 20/20”；最多三个来自 `sectionKeyPoints` 的考点，真实跟练/复查数量，下一段标题。只有 `course.passed === course.total` 才写“120 题已完成”；仅完成末段而前段未完成，写“第 6 段完成，尚有 N 题未完成”。不能把完成等同精通。
- **可访问性：** 总结有标题及 region 名称；主动作仍获得焦点，关联短总结，不移动到无交互装饰。展开完整总结用键盘可达入口；庆祝 seen 标记与进度一起保存，恢复时不补播。减弱动画按共同规则。
- **实现落点：** `src/app.js::judgeNow/renderSectionSummary/renderPostPass/chooseNextAction`；`src/levels.js::sectionTransition/markSectionSummarySeen`；`src/index.html::section-summary` 的位置；`src/style.css`。
- **优先级／改动量：** P1；约 40–70 行。末段动作兜底属于 P0：有未完成题就去真实目标；全库完成则进入待复查或今日收束，不能留下指向空对象的“下一段”。

#### K. 切题：先交接，再开始下一轮

- **触发条件：** 主下一步、目录选择、今日任务跳转、下一段任务。
- **视觉与动效：** 同步清理旧补全、结果有效态、问答上下文、今日收束和正在播放的装饰；新标题用 A 的 160ms，不做整屏滑动。未通过题不显示“通过后的下一项”主按钮；自由选题入口继续可用。当前练习操作区只保留一个强调主动作：编写时运行，已运行时判题，通过时下一步，其他按钮降为次级但保留功能。
- **文案：** 下一步具体到目标：“继续：#08 {短题名}”；清筛选时“已定位下一项，目录筛选已清空”。目标来自 `nextPlanItem`/实际段转移，不能假设序号加一。今日目标达成仍优先“今天先到这里”，继续练为次动作。
- **可访问性：** 点击或键盘选题都先到新题标题，再自主进入编辑器；窄屏不聚焦已关闭的 rail。快速选择时只保留最终题目的焦点与播报；按钮即时可用，动画中可再切题。减弱动画按共同规则。
- **实现落点：** `src/app.js::selectLevel/jumpToQuestion/continueToNext/chooseNextAction/renderNextAction/renderDetail/closePanel`；`src/index.html::q-title/next-action`；`src/style.css`。
- **优先级／改动量：** P0；约 40–65 行。

#### L. 退出与返回：允许停下，并告诉用户保留了什么

- **触发条件：** 任意阶段选择编辑器操作区的次级“今天先到这里”，或已达目标的同名主动作；关闭浏览器本身不拦截。
- **视觉与动效：** 先保存，再在当前反馈位置显示现有 `#today-wrap` 的静态摘要，0ms、无缓动；替换本轮判定反馈而不另开弹窗。不清草稿、不清通过记录，不自动关闭窗口。返回练习时恢复原题与选区。
- **文案：** “今天到这里：新完成 N 题，复查 M 题。下次从 #08 继续。”仅在真实写入后附“草稿和进度已保存到此浏览器”；内存态附“仅保留在本页，关闭或刷新可能丢失”。页面底部的绝对保存承诺也应随实际状态调整。
- **可访问性：** 小结聚焦标题，提供“返回练习”按钮；保存失败提供“重试保存”并保留全部内存状态，不诱导重做、不重复计数。系统关闭没有焦点动作或离开确认；不能承诺 file:// 在任意浏览器永久保存。减弱动画按共同规则。
- **实现落点：** `src/app.js::saveProgress/safeStorage/showTodayWrap/todayWrapText/bindUi/boot`；`src/levels.js::saveState` 返回值由 UI 接收；`src/index.html::today-wrap/actions/foot`；`src/style.css`。
- **优先级／改动量：** P1；约 35–60 行。保存反馈可靠性属于 P0，复用 D 的状态通道。

### 3.4 交付顺序与规模

先做 P0 的基线清理、结果真实性、草稿版本、忙态、成功/失败交接与下一步边界，再做进入/读题/段通关/收束的 P1；P2 仅补求助内容的淡入，不扩展新机制。按上述范围，共享部分合并后估计约 600–950 行触及量，含删除/替换旧规则，不是净新增行数；动效与状态机改造需一并评审。数值是设计估算，没有在本次生成实现补丁或测试代码。

后续实现的新增内联资源目标不超过 20 KiB（相对同一基准构建的字节增量，约为当前产物的 1%），零新依赖、零音频/图片/字体资源；这是建议预算，当前约 1.99 MB 为题设数据，本次未重建测量。若收敛 token、共用函数后仍超预算，先舍弃 P2，不放宽预算。

## 4. 度量的办法

以下是后续实现的验证方案与目标值，不是已取得的测量结果。无头检查使用未来构建出的 `file://` 产物；本次不运行构建、不产生截图、日志或测试文件。建议固定浏览器版本、1440×900 与 1024×768 视口，另测窄屏抽屉和第 5 节宽度边界；记录是否 CPU 降速、是否减弱动画，避免混比。

### 4.1 可观察、可重复的检查

| 检查 | 操作与观察点 | 判定目标 |
| --- | --- | --- |

| 保存与恢复 | 正常保存后重新打开同一浏览器/同一路径；分别模拟 storage 不可访问与 setItem 配额失败，再重试。 | 恢复题号、SQL 和真实进度；失败态明确只在本页；stub 不被误认落盘；重试不增加完成计数。 |
| 视觉与离线边界 | 统计作者样式的字号/色值及资源引用；量主列 bounding box；键盘走查窄屏；在后续构建时比较字节数。 | 四字号、六实色、emoji 0、无 XP/连续/生命值入口；两栏加抽屉，默认主列≥640px；无资源网络请求；体积增量≤20 KiB。对比度正文目标≥4.5:1，焦点/交互边界目标≥3:1，未达标须在六色内调整。 |

自动检查事件顺序、样式和 DOM 状态；真实“已绘制”、屏幕阅读器表现、长查询卡顿仍需人工验证。正常题目与刻意构造的重计算分别记录；不把一次极慢 SQL 的计算耗时归因于反馈设计，也不声称 UI 动效可以解决主线程阻塞。

### 4.2 两个主观问题与比较方法

让 5–8 位目标学习者各走一轮“进入 → 运行 → 结果不符 → 修改 → 通过 → 下一题”，再体验一次段末与退出；原版/方案版顺序交叉，题目难度与草稿长度相近，避免第二次熟练带来的偏差。人工记录寻找下一步的停顿、误以为运行已通过的次数和重复点击次数，作为客观项的补充；不采集 SQL 到远端。

1. 每个结论后问：“刚才发生了什么，接下来该做什么？”记录能否独立复述，并给“清楚、连贯”1–5 分；目标是没有运行/通过混淆，方案版中位数至少提升 1 分。
2. 完成两题和一段后问：“是否感觉有推进、愿意继续，同时没有被催促或惩罚？”分别记 1–5 分及一句原因；推进感目标至少提升 1 分，受催促/惩罚感不高于原版。

若只觉得动画更多、仍说不清下一步，优先调整文案位置与焦点交接；不靠延长动画或追加奖励追分。上述样本仅用于设计方向判断，不宣称统计显著性。

## 6. 不做清单

- 不做音效、背景音乐或震动：离线静音可用，结果不依赖听觉，避免外部资源与额外设置。
- 不做 emoji、吉祥物、彩纸、粒子、奖杯弹窗：保持 HR 工具语境，避免用装饰取代结果依据。
- 不做 XP、连击、连续天数奖励、生命值、答错扣命，也不换名保留有限机会：失败应引向检查与修改。
- 不做排行榜、成就商店、等级经济与强制日目标：段与题的真实完成已经提供推进依据；允许随时停下。
- 不做强制顺序、自动跳题、成功后倒计时：继续或回顾由用户决定，允许自由选题。
- 不做后端、账号、遥测上传、远程 AI 判定或联网问答：保持 file://、零运行依赖与本地隐私边界。
- 不改题库、HR 业务口径、SQLite 结果比对规则或参考库隔离；不把列名不同、查看提示作为判错理由。
- 不做整页转场、长庆祝、逐行瀑布、持续呼吸、滚动数字与每键动画：避免重复练习噪声、动画排队和额外状态组合。
- 不加编辑器框架、动画库、字体/图片/音频文件，不接受超出新增 20 KiB 的实现：体积预算优先于 P2 装饰。
- 本轮不设计 Worker/查询中断架构，也不承诺同步重查询期间可交互；这是另一个性能议题，不能用假进度或假取消包装。
- 本次不实现、不构建、不生成测试脚本/截图/其他文件，不修改现有文件，不执行 git add/commit/push；效果待按第 4 节核验。
